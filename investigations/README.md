# Investigations

This section documents the investigative workflow performed in the Wazuh SOC/SIEM Home Lab.  
The goal is to show how Wazuh alerts were analyzed and correlated to understand suspicious activity on the WordPress server.

The investigation focuses on:
- Authentication failures  
- Suspicious login attempts  
- WPScan brute-force activity  
- Event correlation using Threat Hunting  

---

## 1. Authentication Failure Investigation

Multiple authentication-related alerts were generated by the Wazuh agent on the WordPress VM.

## 3. WPScan Brute-Force Activity

WPScan was executed against the WordPress instance to simulate password guessing and application-layer probing.

### Evidence: WPScan Output

![WPScan Output](../screenshots/17-wpscan-output.png)

WPScan identified:
- Outdated WordPress core version  
- Outdated Twenty Twenty-Two theme  
- XML-RPC exposed for authentication attempts  

While Wazuh did not directly flag WPScan as a tool, its activity surfaced indirectly through authentication failures and related alerts.

---

## 4. Investigation Findings

From the combined evidence:

### ✔ Repeated authentication failures were observed  
### ✔ Threat Hunting confirmed clustered suspicious login activity  
### ✔ WPScan brute-force attempts aligned with the time window of alerts  
### ✔ Wazuh provided OS-level and authentication visibility, but limited application-layer insight  

### Key Takeaways

- Wazuh can effectively surface suspicious authentication behavior.  
- Threat Hunting enables correlation and deeper investigation of events.  
- WPScan activity highlights the need to ingest Apache/WordPress logs for full visibility.  
- Custom rules can further enhance detection of web application attacks.

This investigation demonstrates a SOC-style workflow: starting from alerts, pivoting through Threat Hunting, correlating with external tool activity, and identifying visibility gaps for future improvement.
